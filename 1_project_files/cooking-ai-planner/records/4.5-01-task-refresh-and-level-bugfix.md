# 小饭桌 4.5 Step 1 执行记录

日期：2026-05-24

## 执行目标

修复推荐任务系统中“任务完成后推荐卡片不刷新”和“XP 达到升级阈值后等级反馈不明确”的问题，并保持现有 UI 风格不变。

## 修改原因

4.0/3.0 当前成长任务面板按难度直接展示全部任务，已完成任务只会变成完成态，仍停留在推荐任务卡片中；用户完成任务后看不到新的可做任务。任务经验虽然通过 `totalXp` 可以推导等级，但完成任务返回结果没有明确给出升级信息，反馈不够清晰。

## 实际修改

- 新增推荐任务筛选函数 `getRecommendedTasks()`：
  - 优先返回当前难度下未完成任务。
  - 当前难度任务都完成时，自动回退到其他难度的未完成任务。
  - 默认最多返回 2 条推荐任务。
- 更新推荐任务面板：
  - 使用 `completedTaskIds` 过滤已完成任务。
  - 完成任务后，卡片列表会自动显示下一条未完成任务。
  - 若所有任务都完成，显示“今日任务已完成”的完成态卡片。
  - fallback 到其他难度任务时，XP 和难度标签使用该任务自身的 difficulty。
- 更新 XP 进度逻辑：
  - `completeTask()` 会计算 `previousStats`、`nextStats` 和 `leveledUp`。
  - localStorage 中同步保留 `level` 与 `currentLevelXp` 快照。
  - `totalXp` 仍是等级计算的单一可信来源。
- 更新任务完成反馈：
  - 如果本次领取经验导致升级，toast 显示“升级到 Lv.X”。
  - 未升级时显示“当前 Lv.X”。

## XP 和等级计算逻辑

- 当前每级阈值：`XP_PER_LEVEL = 50`
- 等级计算：`level = Math.floor(totalXp / XP_PER_LEVEL) + 1`
- 当前等级内经验：`currentLevelXp = totalXp % XP_PER_LEVEL`
- 进度条百分比：`Math.round((currentLevelXp / XP_PER_LEVEL) * 100)`
- 是否升级：`nextStats.level > previousStats.level`

本次未改动等级阈值，只增强了完成任务后的返回结果与本地快照。

## 任务刷新逻辑

- 推荐任务面板读取 `progress.completedTaskIds`。
- 当前难度下过滤掉已完成任务。
- 已完成的任务不再长期停留在推荐卡片里。
- 当前难度无可推荐任务时，从其他难度中查找未完成任务作为 fallback。
- 全部任务完成后显示完成态提示卡片，不再重复推荐已完成任务。

## 数据影响

影响 localStorage：

- key：`cooking_ai_planner.v3.task_progress.v1`

保留原字段：

- `totalXp`
- `completedTaskIds`
- `updatedAt`

新增/同步快照字段：

- `level`
- `currentLevelXp`

兼容性：

- 旧数据没有 `level` 或 `currentLevelXp` 时，仍会通过 `totalXp` 正常推导。
- 已完成任务仍通过 `completedTaskIds` 判定，不迁移历史数据。

## UI影响

- 已完成任务不再继续占用推荐卡片位置。
- 所有任务完成后显示一个完成态卡片。
- toast 文案增加升级反馈。
