# 小饭桌 4.5 Step 7 执行记录

日期：2026-05-24

## 执行目标

优化“随机一道菜”功能，让随机生成的菜谱记录可以持久保存，并支持关闭弹窗或页面状态变化后再次点击打开完整详情。

## 修改原因

原随机一道菜只保存当前 `randomRecipe` 内存状态。关闭弹窗或清空当前结果后，用户无法再从记录中重新打开刚刚抽到的菜谱详情，不利于复盘和继续学习。

## 实际修改

- 新增随机菜谱历史服务：
  - `getRandomRecipeHistory()`
  - `addRandomRecipeHistory(recipe)`
  - `clearRandomRecipeHistory()`
  - `normalizeRandomRecipeHistory(input)`
- 随机生成菜谱时保存完整 recipe 对象，而不是只保存标题。
- 首页“随机一道菜”卡片下方新增最近随机记录列表。
- 每条历史记录是可点击按钮，点击后重新打开 `RandomRecipeModal`。
- 弹窗中的“查看详情”继续复用现有 `/recipes/:recipeId` 详情页。
- 最多保留最近 5 条记录。
- 新记录置顶。
- 重复抽到同一菜谱时去重并置顶，避免脏数据堆积。

## 随机菜谱数据结构

localStorage 中保存结构：

```js
[
  {
    id: string,
    createdAt: string,
    recipe: {
      id: string,
      title: string,
      description: string,
      estimatedTime: string,
      difficulty: string,
      ingredients: array,
      steps: array,
      tags: array,
      ...其他详情页需要的原 recipe 字段
    }
  }
]
```

该结构保留完整菜谱对象，能够继续传给随机弹窗和详情页。

## localStorage key

```text
xiaofanzhuo_random_recipe_history
```

## 详情页复用方式

- 历史记录点击后重新打开 `RandomRecipeModal`。
- 弹窗点击“查看详情”后仍使用：

```js
navigate(`/recipes/${recipe.id}`, { state: { recipe, from: '/' } })
```

- 因此详情 UI 继续复用现有 `RecipeDetailPage`，没有新增第二套详情页。

## 数据影响

- 新增 localStorage key：`xiaofanzhuo_random_recipe_history`
- 不影响：

  - 预算账本

- hover/focus 增加轻量边框与阴影反馈。
- “清空”按钮现在清空随机历史记录。
